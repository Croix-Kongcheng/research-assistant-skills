# 自包含写作与格式示例

本文件配合 [SKILL.md](SKILL.md) 使用。下面均为本技能为说明写法编写的假设场景和原创示例，不是私人笔记摘录，不证明某个项目、实验或系统已实际实现。只借鉴解释方法；任务中的技术事实仍须回到本次材料核对。

## 按用途组织

这些是可选组织思路，不是每篇必须填满的模板。

| 用途 | 优先讲什么 |
|---|---|
| 项目原理 | 一个具体输入怎样经过入口、处理和数据存储得到结果；关键失败处理和设计原因。 |
| 需要修改的教程 | 去哪里改、改哪部分、为什么、怎样生效、怎样检查。说明机器、终端和工作目录，区分源码、运行数据与笔记目录。 |
| 排障 | 从现象定位层次，解释每次检查能排除什么，而非堆命令。 |
| 理论与论文理解 | 简要正式解释，再拆真实难点；保留符号、条件、推理、原图与证据。论文事实、自己的理解和待核实疑问分清。 |
| 调研与决策 | 围绕问题、比较口径、选择理由与来源；时效信息写实际查询日期，未实测性能不写成亲测。 |
| 计划、通知与方案 | 使用者和主办方的责任、时间、准备物、步骤及提交物在同一处讲清，不自动扩成手册。 |
| 过程记录与阶段回顾 | 保留当时判断和后来修正，可按实际日期追加，用 `- [ ]` / `- [x]` 表示待办与完成。 |

单篇教程不必拆系列。真正有顺序的成套内容可用一篇总览，说明项目做什么、关键边界和每篇用途；专题按理解或操作链路拆分。不要逐源码文件巡讲，也不要求每节总结。

## 先给作用或入口

假设要解释一个语音笔记程序，可以这样开头：

> 说一句话以后，它是怎样变成一条能搜索的笔记的？先跟着一个例子走：输入“周五整理实验数据”，程序先转写，再提取时间，最后保存正文与提醒时间。

后文始终跟着这个输入，才能看清各模块交接什么。这是说明用的假设输入；没有真实记录时不写成“这次实测输入”。

如果使用者只是要改配置，可以直接写：

> 改识别语言找 `recognition.language`，改输出文件夹找 `output.directory`。保存后重新加载配置，再用一段短录音检查转写语言和保存位置。

上面的键名仅为写法示意。实际笔记要核对本次软件的真实键名和生效方式，不复制假设配置当作操作指令。完整配置或提示词确实是读者要改的对象时，可以保留相关全文。

## 把机制讲清楚

过于空泛：

> 系统采用先进的一致性机制，显著提高用户体验。

有具体因果：

> 取消以后，旧请求可能还在跑。给每次请求分配一个编号，结果回来时先核对编号。编号已经过期，就忽略这个结果，避免旧内容盖住新内容。

口语不能替代机制。自然风格允许“诶，那为什么不能直接保存？”这样的设问，但接下来必须回答。正式风格也可以保留相同推理，去掉口头表达即可。不要按口头禅或感叹号数量验收。

## 理论难点用最小例子讲透

以下是独立的教学示意，不是某篇论文的模型或实验结论。

> 大常数法常用来让一个约束只在某个条件成立时起作用。假设有 $x\leq b+M(1-z)$，其中 $z\in\{0,1\}$。当 $z=1$，它就回到 $x\leq b$；当 $z=0$，右边变成 $b+M$，足够大的 $M$ 可以让这条限制不再收紧已有的可行范围。
>
> 诶，那是不是随便把 $M$ 写得特别大就行？这里的“大”是相对于 $x$ 的有效上下界而言。太小会误删本该允许的方案，远大于必要范围又可能损害数值表现。所以先确定范围，再选足够用的 $M$。

这个例子把二进制状态代进去，但仍应说明 $x$、$b$ 和 $M$ 的量纲、有效范围及模型条件。实际论文若没有给界限或推导，应明确缺失；不能把教学补充说成作者原证明。

有些公式的障碍不在代数，而在含义。假设只为说明累计服务时长，定义 $S=\sum_{t=1}^{T} u_t\Delta t$，$u_t$ 是是否提供服务的指示量，$\Delta t$ 是每段时长。可以用“相同服务量在更早时刻开始，累计服务时长会不同”说明求和含义；必须交代这只是当前假设目标，不把它泛化为所有领域的效用或韧性指标。

遇到原式疑似错误时，先保留原式及所在页 / 式号，再区分 OCR 转写错误、作者定义差异和原文真实疑点。有证据才改转写，原文存疑则写明待核实，不悄悄改成看起来更标准的式子。

## 证据范围写在结论附近

如果本次只检查生成文件，可以写：

> 本次确认文件已生成，图片链接可以定位；还没有在目标编辑器中打开预览。

如果材料里只有他人的测试记录，可以写：

> 资料记录了三组输入的测试结果；本次未重新执行这些测试。

不要把上面任何一种改成“系统已全面验证”。静态检查不等于显示检查，示例数据不等于真实实验，教程推导不等于作者代码或设备已复现。边界贴近相应结论即可，不为普通笔记另加冗长审计表。

## 附件和链接示例

先按 [工作区配置规则](references/workspace-config.md) 解析位置。下面仅假设目标工作区已有这样的最小树，不要求新建它，也不声称示例文件已经存在：

```text
工作区/
├─ 附件/
│  └─ 方法示意.png
├─ 知识积累/
│  └─ 大常数法.md
└─ 论文精读/
   └─ 01示例论文/
      ├─ 00.总览与阅读顺序.md
      ├─ 01.模型.md
      └─ 02.结果.md
```

若实际图片确在上述位置，从 `01.模型.md` 到它需返回两层。Obsidian 可写：

```markdown
![[../../附件/方法示意.png|900]]
```

标准 Markdown 可写：

```markdown
![方法示意](../../附件/方法示意.png)
```

宽度参数只改变显示大小，不会让模糊原图变清晰。实际写入时必须替换成已取得的文件，逐个从笔记所在目录解析路径。不要把本例文件名、临时绝对路径或失效链接当作真实嵌入。

对独立知识的链接也按当前格式选择：

```markdown
[[知识积累/大常数法|大常数法]]
```

```markdown
[大常数法](../../知识积累/大常数法.md)
```

Obsidian 双链可按库根消歧，标准 Markdown 链接通常按当前文件目录解析。不要把两种基准混用。短双链只在名称能唯一解析时使用；表格内双链别名或宽度分隔符写为 `\|`。

外部来源用明确标题的链接，论文原图写题名或引用及图号 / 页码。图为自绘时写明依据；裁剪与改绘说明处理。图必须解决正文中的辨认或理解问题，不能只作装饰。

## 导航按实际用途连接

上述假设论文系列中，`01.模型.md` 可以用以下导航写法；实际目标必须存在：

```markdown
上一篇：[[00.总览与阅读顺序|总览与阅读顺序]]

下一篇：[[02.结果|结果]]

返回总览：[[00.总览与阅读顺序|返回总览]]
```

标准 Markdown 对应写法：

```markdown
上一篇：[总览与阅读顺序](00.总览与阅读顺序.md)

下一篇：[结果](02.结果.md)

返回总览：[返回总览](00.总览与阅读顺序.md)
```

首页链接首篇，末篇省略不存在的下一篇，不循环、不跨论文。拆篇、增补或迁移时同步修复总览和相邻导航。不要把独立的“大常数法”笔记插进论文上下篇；它按主题被多篇论文引用，在相关应用处回链即可。

已有图片和链接有效时不为统一外观重写。外部工具搬文件之后，需要自己核对引用，不能假设编辑器已经自动更新。

## 图表、标题和格式

- 系列篇号是文件的阅读位置，不要求小标题都带相同编号。沿用同组标题层级；无编号结构不强行补号。
- 默认少用 Mermaid；自绘时优先调用可用且适合的 `scientific-visualization`，操作用真实截图，相关图可核验来源与许可后联网获取。Mermaid 仅在明确要求或简单流程 / 时序确有优势时少量使用，短链路可直接写箭头；图节点须对应正文，目标环境不支持渲染时改用可查看的图片或文字。
- 表格只承担字段、比较或阅读地图等并列关系；不要把整篇因果推理切成格子。
- 代码围栏注明语言；代码、伪代码、缩略片段和可运行完整文件分清。命令给出执行目录、终端、替换项、生效与检查条件。
- 行内数学用 `$...$`，行间用 `$$...$$`，符号、上下标和学科记法保持一致。单位与成立条件就近说明。
- 加粗、callout、标签、emoji 和笔记 frontmatter 按任务和工作区选择，不默认新建一套标签或模板系统。技能自己的 YAML 元数据与普通笔记 frontmatter 不是同一件事。

## 文末生成与更新信息

以下是字段格式示意，不是可以原样照抄的真实生成信息。实际任务应读取完成时钟和可确认的模型标识，替换这些值：

```text
生成时间：实际日期 实际时分秒（实际时区或UTC偏移）

生成模型：本次可确认的实际模型名称或 ID
```

此块放在来源、相关链接和系列导航之后，属于全文最后的正文内容。其他语言可以使用对应字段名，仍要有时间、时区与模型。

旧笔记应保留可核实的历史信息，再记录本次更新：

```text
更新时间：本次实际日期 实际时分秒（实际时区或UTC偏移）

更新模型：本次可确认的实际模型名称或 ID
```

历史生成信息未知就写“未知（历史生成信息未记录）”；当前环境没有模型标识就写“未知（当前环境未提供模型标识）”。不要根据产品名、旧会话、文件修改时间或示例猜模型和生成日期。

交稿前先对照原材料检查关键图片、公式、条件、步骤和来源，再删重复；最后查看链接、图片实际可读性、导航、围栏、数学定界符和文末信息。只能报告本次真正做过的检查。
