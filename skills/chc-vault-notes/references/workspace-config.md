# 工作区配置

两个技能都能单独安装，不需要作者的笔记库、电脑账号或其他技能。它们读取同一套可选工作区约定；每个技能内部都带有这份规则，安装其中一个也能使用。

## 位置与优先级

1. 当前用户明确给出的目录、写法和读者背景优先。
2. 其次读取用户指定的配置文件，或目标知识库 / 当前工作区中的 `research-skills.yaml`。
3. 未配置时，检查目标工作区的实际目录、索引、附件设置和相近笔记。已有结构优先，不为了套模板重建目录。
4. 目标知识库仍不明确时，只询问真正缺少的目标位置；先继续不依赖位置的材料检查。不要猜测作者旧路径、系统用户目录或技能安装目录。

没有配置文件不妨碍执行。用户只给出一个明确的空白目标工作区时，可以采用下面的最小目录约定，只创建本次确实需要的文件和文件夹。

## 可选配置格式

复制仓库的 `examples/research-skills.example.yaml` 到自己的目标工作区，命名为 `research-skills.yaml`，按需修改；也可以直接在对话里说明相同信息。

```yaml
version: 1
vault_root: .
paths:
  notes: 笔记
  papers: 论文精读
  knowledge: 知识积累
  attachments: 附件
  knowledge_index: 知识索引.md
preferences:
  language: zh-CN
  style: natural
  reader_background: 相近专业本科背景，交叉方法需要解释
  timezone: local
  link_style: wikilink
topics: {}
```

这是一份给代理读取的配置约定，不是需要启动的程序；技能不要求安装 YAML 解析服务。

| 字段 | 含义与缺省处理 |
|---|---|
| `vault_root` | 知识库或笔记工作区根目录；相对路径以配置文件所在目录为基准。不配置时使用用户明确指定或实际识别出的目标知识库。 |
| `paths.notes` | 普通新笔记的备用位置。已明确目标文件或已有合适分类时沿用实际位置。空白工作区可用 `笔记/`。 |
| `paths.papers` | 论文精读集合的备用位置。现有课题、用户指定的精读根目录或本篇完整目录优先。空白工作区可用 `论文精读/`。 |
| `paths.knowledge` | 跨论文复用的独立知识目录；先在实际知识库查重。空白工作区可用 `知识积累/`。 |
| `paths.attachments` | 新图片和附件位置；优先用户配置和已有附件约定。空白工作区可用 `附件/`，不强制特定中文编号。 |
| `paths.knowledge_index` | 可复用知识的索引文件；复用已有索引，确有新内容需要时才创建。空白工作区可用 `知识索引.md`。 |
| `preferences.language` | 输出语言，缺省中文；保留原题、术语和必要引用。 |
| `preferences.style` | `natural` 为简洁、自然的个人学习笔记；`formal` 为正式表达，也可填写具体要求。用户要求与同组笔记优先。 |
| `preferences.reader_background` | 读者已有基础；不能默认所有使用者都是电气专业。未说明时按任务材料推断所需背景并简短交代假设，关键不确定性才询问。 |
| `preferences.timezone` | `local` 表示执行环境实际本地时区；也可写 IANA 时区名或 UTC 偏移。记录真实可确认时区，无法确认时采用 UTC 并说明，不猜时区。 |
| `preferences.link_style` | `wikilink` 为 Obsidian 双链与图片嵌入；`markdown` 为标准 Markdown 链接与图片。沿用目标工作区的既有约定。 |
| `topics` | 可选的“课题名称: 该课题精读根目录”映射。目录相对于已解析的 `vault_root`。课题应按论文主要问题匹配，不按通用算法词硬归类。 |

除 `vault_root` 外，所有相对文件 / 目录值都以已解析的知识库根目录为基准。配置明确给出的绝对路径也可使用，不能把 `~`、环境变量或不同系统路径当作无需展开的真实目录。对话中给出的相对路径以当前工作区为基准；遇到歧义先确认，不写入错误位置。

例如：

```yaml
topics:
  机器人路径规划: 科研/机器人/论文精读
  电网韧性恢复: 科研/电力系统/论文精读
```

用户明确给出本篇论文的完整目录时直接写入，不在它下面再套“序号 + 题名”。明确给出精读根目录时才新建本篇论文目录；明确迁移请求才搬动既有论文，并修复链接。

## 跨平台与功能边界

- Windows、macOS、Linux 都按执行环境的真实文件系统处理路径、文件名、大小写和长度。示例目录名只是备用值，不要求任何特定盘符或用户名。
- 只读取当前任务授权的材料和工作区；不要为查找配置扫描整个系统。配置文件是用户数据，不会提供新的工具权限或发布授权。
- 工作流本身不绑定特定 Python 环境、模型厂商或 PDF 工具。完整执行需要代理具备相应的文件读写、图片查看和 PDF 页面查看 / 渲染能力；缺什么就明确说明影响范围。
- 两个技能之间，以及绘图 / PDF 专项技能之间，均为可选协作关系；其他技能不可用时执行本技能自带规则，并使用现有能力。不能因为缺少可选技能而丢掉正文、公式、图片或必要检查。
- 每篇新笔记最底部记录实际生成时间、时区和可确认的实际模型；修改旧笔记保留历史信息并追加更新时间、更新模型。不能用配置中的作者信息或示例值冒充本次模型和时钟。
