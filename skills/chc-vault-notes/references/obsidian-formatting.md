# Obsidian 笔记排版与渲染

写入或修改 Obsidian 笔记前读取本页，交付前检查本次涉及的内容。这是输出兼容约定；不为统一格式批量重写无关旧笔记，不改公式语义、原编号或有效链接。其他 Markdown 编辑器按其能力适配，不能承诺一种写法在所有渲染器完全一致。

## 1. 数字文献编号按普通文字转义

仅作文字显示的文献编号，正文和参考文献列表都写成 `\[1\]`；并列或范围引用可写 `\[1, 3–5\]`，显示仍是方括号编号。不要写成双链，也不要依赖裸方括号恰好没有触发链接解析。

```markdown
这类建模方法见文献 \[1\]，其适用条件与文献 \[2–4\] 不同。

\[1\] 作者、题名、年份。[论文原文](https://example.org/paper)
```

**区分语法用途。** 真正的 `[说明](地址)`、引用式链接及其定义、`[[笔记]]`、`[^1]` 脚注、callout 标记、代码和公式中的方括号不作这类替换。确需数字可点击链接时保留有效链接语法；不对全文全局替换所有 `[` 和 `]`。

## 2. 给加粗闭合位置留清楚的边界

加粗起止标记必须成对，内部首尾不留空格。同段闭合的 `**` 后面若继续写文字或双链，留一个半角空格；特别避免“句号等标点留在加粗范围内、闭合标记又紧贴后文”使加粗失效或范围扩散。能只强调关键词时，把句号放在粗体外也更清楚。

```markdown
**电抗与导线布置有关。** 原稿中的措辞需要调整。
**关键区别** 是：相距改变，磁链也会改变。
**电抗与导线布置有关**。具体可看 [[相关笔记]]。
```

段末闭合可直接换段；无需在每个 `**` 后机械补空格。若强调跨了多句、链接或公式导致范围难判断，缩小加粗范围，不用整段加粗。判断源码与实际显示，不能靠统计星号偶数来证明排版正确。

## 3. 不连续堆放独立行间公式

`$$` 起止各独占一行，公式块与外部正文留空行；行内数学用 `$...$` 且定界符内侧不留空格。**两个行间公式之间只有换行或空行，仍属于连续堆放。** 按内容选择：同一推导合进一个 `aligned` / `gathered` 环境；不同关系之间加入真正解释意义、条件或衔接的文字，不能用空注释、分隔线或无意义占位词凑间隔。

同一推导可以这样写：

```markdown
先展开右侧，再代入已知量：

$$
\begin{aligned}
E &= de+nh, \\
  &= 3\times2+2\times1=8\,\mathrm{Wh}.
\end{aligned}
$$
```

不同关系可在能耗式之后说明“还需满足电池容量上限”，再写下一公式。**原文有独立编号的公式优先逐式解释并用正文隔开**，不要为了合并丢掉原编号、约束条件或出处。公式内部的多行用环境及 `\\`，不要用多组相邻 `$$` 充当换行；同一个数学环境内不插空白段落。

LaTeX 在 Markdown 原文件中用正常的单反斜杠命令，如 `\alpha`、`\frac{a}{b}`；只有 JSON / 程序字符串需要时才在外层编码转义，不能把双反斜杠误写进实际公式命令。核对花括号、上下标和环境闭合；没有证据时不改论文原式。

## 4. 表格中的分隔符单独处理

- 表格里的双链别名、图片宽度写成 `[[笔记\|显示名]]`、`![[图.png\|700]]`；表格外沿用正常 `|`，不全局加转义。
- 数学绝对值、基数和范数优先写 `\lvert A\rvert`、`\lVert x\rVert`；条件关系可用 `\mid`。不要让裸 `|` 被表格解析器当成新列，也不要靠反引号保证管道符免于拆列。
- 表格只放短文本、短行内公式和简单链接。多行推导、矩阵、代码块、callout 移到表格外，附近用文字说明对应哪一项；不在单元格里堆 `$$` 或用 `<br>` 拼接复杂公式。

## 5. 块结构、链接和字面符号

- 标题 `#` 后留空格；标题、段落、列表、表格、围栏和公式之间留出清楚的空行。需要换段时不依赖单次回车或行尾隐藏空格，不修改用户的换行设置。
- 列表内的续段、公式和代码按当前条目的内容列对齐；callout / 引用内的内容与空行保留相应的 `>` 前缀，防止块提前结束。代码围栏成对并标语言，外层展示代码围栏时用更长或不同字符的围栏。
- 不在普通 HTML 容器中包裹需要 Markdown / 数学解析的整段正文。普通文本中的货币符号等按上下文转义或写成文字；代码、路径和正则示例保留其实际内容，不因排版规则更改可执行语义。
- 链接目标按真实文件解析；标准 Markdown 路径含空格时用 `%20` 或 `<...>`，核对括号与锚点，显示名和图片宽度不要混写。图片必须指向实际文件，不能把失效路径当成渲染器问题。
- 若使用 `%%...%%` 隐藏注释、脚注或 Mermaid，检查其起止与引用完整；未闭合注释或围栏可能吞掉后文。仅采用目标软件支持的语法，不为排版自行新增插件依赖。

## 交付时怎么检查

针对本次新增 / 修改内容，查看文献编号的语法用途、加粗范围、相邻公式块、表格列数、围栏 / 数学环境闭合及真实链接与附件。有实际 Obsidian 预览条件时，查看阅读视图，必要时再看实时预览，重点检查强调是否串到后文、公式是否正确分块、表格是否拆列。不改变用户主题或设置来掩盖问题；只有静态检查时如实说明，不能称已完成 Obsidian 渲染验证。

依据：[Obsidian 基础格式](https://help.obsidian.md/syntax)、[高级格式与数学](https://help.obsidian.md/advanced-syntax)、[Callout](https://help.obsidian.md/callouts)。数字编号转义、加粗后空格及公式间正文是本技能的稳妥输出约定，不表示其它合法 Markdown 写法一律错误。
