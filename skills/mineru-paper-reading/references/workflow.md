# 完整精读与知识积累工作流

本文件自包含全部执行要求，不依赖作者的私人提示词、笔记样本或其他技能。三种模式都先读 [工作区配置](workspace-config.md)，按同一套规则解析目录与偏好；续写和审校另读 [模式要求](modes.md)。

输出 Obsidian 笔记前读取并执行本技能自带的 [排版与渲染规则](obsidian-formatting.md)。纯文本数字文献编号写成 `\[1\]`，同段闭合加粗后续接正文时留空格；加粗范围不得包含双链、普通或引用式链接，链接显示文字与别名也不加粗；独立行间公式之间用实际解释衔接，同一推导可合并环境，不能为了排版丢掉原编号或条件。最终检查包含这些规则及表格、围栏、链接的实际显示；没有 Obsidian 预览时只报告静态检查，不把代码、数学、脚注和真正链接一并转义。

## 1. 输入、目标与能力

接收本次已有的 MinerU 解析目录，检查实际 Markdown、结构化 JSON、图片和源 PDF；PDF 在别处也可给出路径，不假定固定文件名。用户可补充知识库根目录、论文目标位置（精读根目录或本篇完整目录）、研究课题，以及读者基础、文风和语言。材料路径不等于默认输出目录，不把笔记写回原始材料或技能安装目录。

按“用户明确要求 → 可选工作区配置 → 实际目录与相近笔记 → 明确空白目标工作区的最小备用结构”确定落点。路径、知识索引、附件位置和链接格式均用已经解析的实际值，不能照抄别人的目录树。只在当前任务授权的材料和工作区内查找。

目标是让本次读者看懂每节、每个实质性段落、全部公式及关键图表，解释符号是什么、关系怎么来、为什么需要，以及它实际表达或限制了什么。读者背景遵从用户和 `preferences.reader_background`；未说明时依据材料简短交代合理假设，不默认某个专业或研究方向。输出语言和自然 / 正式文风可配置，默认简洁自然中文，但精读范围不能因精简而缩水。

本技能从已有解析结果开始，不部署或运行 MinerU。完整执行需要代理能读写文件、查看图片和 PDF 页面的实际图像。先检查可用能力，使用现有工具；其他写作、绘图或 PDF 技能只有在可用且有帮助时才选用。缺少必要材料或能力时继续能确认的内容，并准确说明未完成的检查与缺什么，不用另一轮文字 OCR 冒充页面核验。

## 2. 认清材料与已有笔记

1. 核对论文正式题名、作者、年份、发表来源、DOI、源 PDF 和正文主文件；不确定的元数据保留未知。先通读结构，再细读，不能只凭摘要和结论补写中间内容。
2. MinerU 用于检索和理顺结构。公式原式、上下标、正负号、编号、跨栏顺序、图表数据和疑点，以源 PDF 核对；公式或表格有疑点时查看对应页实际图像，不仅依赖另一次文字提取。跨栏或跨页的同一自然段合并理解，页眉页脚不当作正文。
3. 在目标知识库内按正式题名、DOI 或源 PDF 身份查找同篇论文；再看目标目录、知识索引和相关概念。已有批注、疑问、个人表达和有效内容都保留，不因为重新归类生成重复副本。
4. 已有写作规范和一两篇相近笔记可用于校准表达，但不把它们的技术结论、旧配置或历史路径当作本次证据。找不到样本就使用本技能的表达规则，不去寻找作者的电脑或私人笔记库。
5. 简短说明保存位置与按内容拆篇的安排后直接完成，不逐篇等待批准。只有论文身份、关键材料或目标位置确实无法判断时才询问。缺少源 PDF 时继续可确认部分，具体标出尚未按 PDF 核验的段落、公式或图表，不声称核验全文。

## 3. 论文放在哪里、怎样组织

### 选择位置

- 当前用户明确指定的保存目录或研究课题优先。目录可在知识库内，也可为用户明确指定的其他输出位置；给出本篇完整目录就直接写入，不再套一层“序号 + 题名”。明确给出精读根目录时才在其下建论文目录。只指定课题时先匹配配置 `topics` 与实际课题树。
- 已有同篇论文优先复用，续写与审校沿用已确认的位置。用户明确要求将已有笔记改存 / 保存到新位置时才迁移，修复所有受影响的索引、引用、导航和图片相对路径，保留批注与有效内容。默认保留原目录名和序号；本次明确要求重新编号时才改号，不因自动归类擅自搬动旧论文。
- 未指定位置时，按论文主要研究问题、目标与主要贡献检查已有课题及其精读目录。不能仅凭应用场景或通用方法词归类。例如同样出现“任务分配”或“回归”，核心问题可能属于完全不同课题；任何示例都不是穷尽分类。
- 没有既有匹配课题而主要主题明确时，在配置或实际结构确定的论文集合位置下合理新建课题及精读目录；已有课题沿用真实目录名，不强改成某个编号。多个归属同样合理且影响保存位置时才简短澄清，同时继续材料身份和阅读结构检查。
- 无既有结构且用户已指定空白目标工作区时，可使用工作区配置约定中的最小备用目录，只创建本次需要的内容；目标工作区本身未明确时不猜路径。

### 文件与阅读地图

1. 未指定本篇完整目录的新论文，各自建立论文文件夹；沿用选定精读根目录的既有命名。需要编号时用至少两位序号紧接论文正式原题，“+”表示拼接而不是额外字符；只取该根目录最大已用序号的下一号，不硬编码首号、不全库统一编号、不为补缺号重排旧论文。配置主题映射对应不同根目录时分别编号。
2. 文件名处理遵从执行平台的真实限制，必要时替换不允许的字符、处理路径长度，并在首页保留正式完整题名。不能把某台 Windows 电脑的盘符或用户名当作跨平台约定。
3. 论文目录通常包含总览与阅读顺序、必要的符号 / 建模约定、按实质内容拆分的专题，以及确有必要的疑点记录。总览默认可命名为 `00.总览与阅读顺序.md`，语言和已有命名可适配；专题数量服从论文，不固定篇数，不产生凑数空笔记。
4. 总览给出正式原题、输出语言下的题意、可确认的作者 / 年份 / 发表来源 / DOI、实际 PDF 与 MinerU 正文入口，以及阅读地图。说明 PDF 页码按文件第几页计算，避免和印刷页码混淆。没有确认的元数据不猜。
5. 论文是一套有阅读顺序的笔记。每个专题正文结束后，按阅读地图保留“上一篇”“下一篇”“返回总览”的真实链接；首页篇尾链接第一篇，第一篇的上一篇指总览，末篇省略不存在的下一篇，不循环、不跨论文。移动、拆篇或增补后修复相邻导航和总览地图。
6. 链接按工作区偏好使用 Obsidian 双链或标准 Markdown。Obsidian 示例可写 `上一篇：[[./实际文件名|实际标题]]`，标准 Markdown 则写 `上一篇：[实际标题](./实际文件名.md)`；实际执行替换成真实已存在的文件。独立知识去系列化的规则不适用于论文导航。

## 4. 全文与全部数学关系

1. 按原文顺序覆盖摘要、引言、各节与小节、方法、算例 / 实验、讨论、结论，以及附录中有实质内容的部分。每个正文自然段都能找到对应解释，可用“原文第 X 节第 Y 段 / PDF 第 Z 页”等简短定位；段落按 PDF 重新判定，不照搬错误 OCR 换行。
2. 每段解释作者在说什么、为什么放在这里、与前后内容有什么关系。难点详细拆开，普通背景直接讲清；用自己的话概括，不机械逐句翻译，不大段贴原文充数。贡献、假设、适用条件和限制都要留下，不能只记方法优点。
3. 全篇编号公式、未编号公式、行内数学关系与符号定义全部覆盖，摘要和附录中的也算。保留作者原编号，教学补充另作标记，不混成论文公式。
4. 每条公式附近讲清目标或物理 / 逻辑关系；符号、上下标、集合、索引范围；参数与变量的区别；单位、参考方向、定义域和成立条件；以及和前后式子的关系。解释“怎么来”时补出必要的移项、代入、守恒、状态枚举或推导，不只念符号。
5. 这是信息要求，不是给每条公式重复一套小标题。同一符号可在总表统一定义并就近提醒；符号重用或含义变化时重新说明。数学符号、上下标、公式与带单位的数学量用 LaTeX，行内 `$...$`，行间 `$$...$$`；公式截图不能作为唯一解释。
6. 对真正卡住理解的条件约束、线性化、近似、松弛、连通性、统计假设或其他专业步骤，按需代入状态，给可手算例子或反例。区分“只要 / 只有 / 当且仅当”、必要 / 充分条件、精确等价 / 近似 / 放宽可行域；不能因最终模型的名称就声称全部处理均严格等价。
7. 原文没给推导就说论文未展开；自行补出的部分标“理解补充 / 教学推导”并说明假设。依赖外部文献而未读到证明时说明依据范围，不编造作者的证明过程。
8. 表格、图注、算法步骤和关键结果也解释清楚：变量如何设置、比较什么、坐标与单位是什么、结论由哪些结果支持。保留理解需要的原图、关键表格和数值；不从像素猜精确数据，不把自拟例子当成作者实验。保留必要参考文献编号和定位，解释关键引文在本文的作用，未读引文全文时不补写具体实验结论。
9. OCR 错误须回查 PDF 后修正转写。若 PDF 本身疑似有错，保留原式和位置，先核对符号、方向和作者定义，再写疑点依据、可验证反例或带条件的候选修正。证据不足写“待核实”，不静默改成标准答案。论文声称、自己的解释、外部补充和仍存疑的内容应能分辨。

## 5. 独立积累可复用知识

1. 依据本次读者基础，主动识别真实理解障碍：超出其背景的方法，或虽听过但不足以理解论文的概念。不对所有人假定同一专业，也不固定每篇论文应产生哪些概念或多少篇笔记。
2. **先查重，再决定是否建篇。** 在本次目标库的知识目录、知识索引及相关课程 / 项目 / 科研笔记中，分轮搜索正式名、别名、中英文名称、常用缩写、同义表达和正文中的定义 / 方法；索引未收录或文件标题不同不等于没有。打开候选笔记，按定义、成立条件和方法实质确认是不是同一知识点，不能只比较文件名；同词异义或跨领域条件不同则明确区分。
   - 已有类似笔记且讲的是同一概念、足以支持本次理解：直接在论文正文链接它，不另写一篇，也不为了本篇论文重写已有内容。
   - 已有同一概念，但确实少了必要解释、条件、例子或有助理解的图：只在原笔记适当位置补缺，保留原内容、批注、来源和有效链接，再从论文链接过去；换文风、换标题、新论文应用或补图不能成为重复建篇的理由。
   - 只有确无对应笔记、或实为需要区分的新概念时才新建，题名写清区别。若已存在多篇相近笔记，优先链接最适合的一篇，不擅自删除或整合既有笔记。
   - 同批候选概念先合并同义名称，落盘前再次检查本批已建 / 已补的文件，后遇到同一概念就复用。检索不足时不声称已完成全库查重；只需简述实际范围，不把内部检索清单堆进正文。
3. 新概念按实际知识目录的领域与主题分类，超出现有主题时再合理增加分类。文件直接用清楚概念名，不以本次论文建立知识子库，不加连续篇号、固定学习顺序或上一篇 / 下一篇，也不以“某论文阅读基础”作为通用知识库名称。
4. 确需新建时，一个有独立理解价值的概念单独成篇；同义词和紧密耦合内容可在同篇解释。普通符号不必都拆词条，多个重要方法也不能塞成大杂烩。数量服从真实缺口，不因本篇论文或某次批次重新建一套已有概念。
5. 每篇先简述来历、正式名称或准确解释，再把本质讲清。围绕“为什么需要它—实际做了什么—怎样用例子想通”自然展开，必要处保留公式、符号、单位、前提和反例，不统一套定义 / 用途 / 证明 / 易错点的教材模板。
6. 正式定义和标准方法优先核对可靠教材、原始论文或官方资料；外部引用核实内容与链接。论文自己的事实仍据提供材料，外部资料只作明确标注的知识补充。无法取得或确认来源就说明，不编参考文献。
7. 通用原理留在知识笔记，论文专属参数、特殊假设、结果和原式疑点留在论文笔记。知识笔记用简短应用链接联系论文，不能把一篇论文特例升级成普遍定义。
8. 论文正文讲到概念时就近链接知识笔记；知识笔记在应用例子或相关位置反向链接实际论文专题。相关概念自然互链，按实际知识索引更新对应分类。不要只在首页堆链接；正文仍需说清论文这一步的含义。

## 6. 写法、图片与链接

默认先简单交代问题来历或正式解释，再用自然表达说透本质，像自己已想明白后留给以后查阅的笔记。自然的设问、旁白和感叹应推动真实推理，不按口语词数量达标，不给严肃段落机械贴“啊”。用户要求正式文风时使用正式表达，内容与证据要求不变。

多用自然段把原因、例子和公式接起来，普通内容简洁，难点完整。少用讲师布置课程的模板，不用重复表格和清单制造篇幅。公式仍严谨，不能用轻松口吻遮盖条件，也不能虚构“我实测过”“研究了一整晚”等经历。

1. 图片实际保存到解析出的附件目录，按工作区已有集中或相对位置约定处理，不强制叫某个编号目录。文件名能区分论文与图号；复用前核对内容，不覆盖无关附件，不移动原始材料。
2. **论文精读与知识笔记都优先用图帮助理解。** 阅读和组织内容时就找出适合用图讲的结构、机制、空间 / 几何关系、状态变化、流守恒、时序及公式含义，安排实际图片配合讲解，避免本可图解的长段落只堆文字。论文笔记优先使用 MinerU / 源 PDF 原图；知识笔记优先复用库内已有合适示意和附件，不因补图另建同概念笔记。保留必要图例、坐标、单位和上下文，打开核对后就近嵌入。简单概念不勉强加图，不设每篇或整套图数配额。
   本地图片不足时，参考 `chc-vault-notes` 的联网配图方式：当前有联网能力且用户未禁止时，主动检索原作者、官方资料或开放资源库的相关图，打开原始发布页核对作者 / 机构、实际内容、使用许可及适用限制，再查看原图核对对象、版本、标注、坐标和正文事实；不能只凭缩略图或搜索摘要。选择允许本次用途的图，下载到实际附件目录，图旁给原始页面、作者、许可链接及实际裁剪 / 标注 / 改绘，并说明看哪里、说明什么。遵从用户指定来源；查不到、许可不适用或不可联网时，依据已核实内容自绘或说明具体缺口，不留失效图片占位。网上图片不能冒充本次实验或用户设备的证据。这些规则由本技能完整携带，写作技能不可用也照常执行。
3. 自绘说明用途和依据，假设数字标明示例；生成插画不冒充实拍、界面截图或论文实验数据。原图注明论文图号及 PDF 页码，裁剪、标注或改绘另行说明。
4. 适合自绘时主动用当前可用的绘图能力，先读所用技能的说明，例如 `scientific-visualization`；没有合适技能则用现有工具，不要求安装特定工具。精确结构、数学关系和数据图优先代码、SVG 或科学绘图，图像生成用于合适插画。不能只写“建议配图”就结束；实际获取 / 绘制、保存并嵌入，图旁说明看哪里、得出什么。交互可辅助探索，笔记内仍留可独立阅读的静态图或可直接渲染的图解。
5. 按实际链接格式嵌入图片：Obsidian 如 `![[实际相对路径/图片.png|700]]`，标准 Markdown 如 `![说明](实际相对路径/图片.png)`。按真实目录深度计算相对路径，文件名有空格等情况正确编码 / 处理，逐个核对实际目标。
6. Obsidian 跨目录链接用可解析的库根或明确相对路径；重名时消歧，表格中的别名 / 宽度竖线写成 `\|`。标准 Markdown 则用真实相对文件链接及可靠锚点，不声称普通 Markdown 阅读器支持 Obsidian 专用语法。

## 7. 进度、检查与文末信息

持续落盘，不等全部读完才一次写入。确因上下文或工具中断而分批执行时，记录可定位的简短进度：完成哪些节 / 段 / 公式，下一处在哪里，哪些知识已新建 / 补充 / 复用，还有什么材料缺失。进度不代替正式笔记；无必要不把内部过程堆进正文。续做先核对实际文件与原文，不凭旧完成声明，也不从头覆盖。

完成前逐项核对：

- 正文、章节、全部数学关系、图表、算法和实质性附录覆盖到哪里；符号、单位、数值、条件与来源是否一致。
- 知识是否已按名称变体和正文查重并阅读候选，现有同概念笔记是否直接复用或只补真实缺口，新建是否确无重复（包括本批文件）；论文特例与通用定义是否分清，个人批注和有效内容是否保留，索引是否准确更新。
- 论文及知识笔记中有助理解的原图 / 知识示意是否实际嵌入，适合视觉解释的难点是否仍是长段纯文字；新增图是否清楚、相关且有来源，联网图是否核实原页与许可，缺图处是否具体说明原因；不以图片数量或装饰图代替质量。
- 每篇论文专题导航是否齐全、相邻篇是否互指、总览地图是否一致，首尾是否真实；独立知识没有混入论文顺序链。
- 新增 / 修改链接与附件是否命中真实目标，表格、围栏、LaTeX 定界符是否完整；自绘图中文、符号、单位与箭头是否对应正文。渲染条件可用时检查实际显示，只报告真正执行的检查。
- 不能将文本精读说成作者代码复现、求解成功或实机验证。没有材料的参数、结果、日志不补造；未解决事项给具体位置、证据缺口和影响，不笼统声称“已经全部验证”。

每篇新论文笔记和独立知识笔记，在全文最底部、来源与导航之后，分别成段记录：

```text
生成时间：实际 YYYY-MM-DD HH:mm:ss（实际时区名或 UTC 偏移）

生成模型：本次实际可确认的模型名称或 ID
```

时间读取本篇实际完成时的时钟。按用户时区配置；未配置则用执行环境实际本地时区，无法确认时采用 UTC 并说明，不猜时区，不把资料发布日期当生成时间。模型只用当前会话或执行工具明确提供的标识，无法确认时写“未知（当前环境未提供模型标识）”，不照抄示例或猜版本。其他输出语言可翻译字段名，但信息不可少。

修改已有笔记与索引时保留可确认的原生成信息，在同一文末块追加或更新“更新时间”和“更新模型”。历史信息缺失且无法核实时写“未知（历史生成信息未记录）”；不能用文件修改时间倒推最初生成，也不能把本次修改冒充最初生成。文末信息的完整性和真实性纳入完成检查。

最终只简短给出论文笔记入口、知识索引、新建 / 补充 / 复用的知识点、实际完成的检查，以及未解决的具体疑点。文件存在不等于全文已核验；静态检查不等于目标笔记软件渲染，也不等于实验复现。
